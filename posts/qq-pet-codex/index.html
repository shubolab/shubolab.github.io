QQ 宠物赛博复活：这次它不吃元宝

我把那只熟悉的企鹅塞进了 Codex。表面上是怀旧，背后却意外地像一次正经的软件交付。

2026-08-09Shubo6 min

前阵子看到 Codex 支持桌面宠物，我第一反应不是“挺可爱”，而是：那 QQ 宠物是不是还能抢救一下？小时候它住在屏幕右下角，饿了要喂，脏了要洗。现在大家都忙着写代码，喂食这套流程显然太重，于是我给它换了份工作——在 Codex 里陪我等任务。

QQpet-codex 就是这么来的。仓库里不只是几张 GIF，而是一套完整的 Codex v2 宠物包、安装 Skill、重建脚本和 QA 记录。做完以后回头看，我对一只企鹅的交付标准，已经悄悄超过了不少内部小工具。

先让它符合 Codex 的规矩

Codex v2 的宠物不是一组随便命名的图片，而是一张有固定合同的 spritesheet：1536 × 2288，8 列 11 行，每格 192 × 208，RGBA 无损 WebP，配置里的 spriteVersionNumber 必须是 2。动作放错一格，结果不是“有点瑕疵”，而是企鹅可能用失败姿势跟你挥手。

这张图集包含 idle、hover、thinking、review、waiting、waving、failed、左右移动和 16 个看向方向。能沿用的动作我尽量保留，running-right、running-left、waving、failed、waiting、thinking 和 review 都与上一份通过验证的 v2 图集逐像素一致。怀旧项目最怕一激动全部重画，最后只剩名字还是原来的。

真正费时间的是“站着不动”

旧 idle 放进新版图集以后显得偏小、偏软，跟 thinking 来回切换时尤其明显。最后我没有把旧图放大锐化，而是重新做了一组六帧呼吸和完整眨眼。新版 idle 的平均可见边界从约 130 × 146 提升到 156 × 198，包围盒面积增加了 62.69%。说人话就是：它终于不是远远站在工位门口了。

Hover 也跟着重画了一次。原因很朴素：对比图摆在一起，它明显小一圈。这个问题如果写进报告叫“视觉体量不一致”，如果直接看图，脑子里只会冒出一句：它怎么突然缩了？

企鹅转头，也得做 QA

项目里保留了 16 个看向方向，并按新 idle 的中性帧重新注册，使用的比例是 0.7096774193548387。小数点这么长，不是为了显得专业，而是少一截就真的会抖。方向图后来做了三轮独立盲测，硬基数方向全部通过，几个靠近基数的中间角度留下了复核备注，但没有象限反转、方向重复或身份漂移。

图集本身也跑了完整验证：PNG 和 WebP 解码后 0 个变化像素；从已提交素材干净重建，结果与内置包字节一致；色键去溢色只执行一次，alpha 没变；最终校验 0 错误、0 警告。这些指标放在桌面宠物上多少有点用力过猛，但“它大概没坏”听起来实在不适合写进发布说明。

安装要安全，也要能后悔

仓库级 Skill 在 .agents/skills/qqpet-codex。只验证时，它只检查包，不碰现有配置。安装时，先在一次性的隔离 CODEX_HOME 里预检；通过后才更新真实配置。已有版本会先搬到带时间戳的备份目录，安装结束再从最终路径验一次。

这个流程解决的不是“安装会不会成功”，而是“失败以后能不能体面地回来”。桌面宠物可以偶尔撞墙，安装脚本不行。

只验证，可以在 Codex 里这样说：

使用 $qqpet-codex 只验证仓库内置的 QQpet-codex v2 宠物包，不要安装。

需要安装，则明确告诉它先做隔离预检：

使用 $qqpet-codex 安全安装仓库内置的 QQpet-codex v2 桌面宠物；
先用隔离的 CODEX_HOME 预检，再安装到我的真实 Codex 配置。

安装完成后刷新宠物列表，重新选择 QQpet-codex。只有刷新仍然没加载新图集时才重启 Codex。先刷新再重启，是我能给这只刚复活的企鹅最基本的尊重。

最后

仓库原创的代码、文档、生成美术和 QA 材料以 CC0 1.0 发布，同时保留了 chenboos5/QQpet-codex 的来源链说明。QQ、QQPet、QGG、Codex 等名称和标志仍属于各自权利人，这个项目也不代表腾讯或 OpenAI 的官方续作。

它只是一次很私人的技术考古：把小时候熟悉的东西捡回来，按今天的工程习惯重新装好。喂养按钮没有回来，校验和倒是有了。也挺符合这个时代。
