别再背 IP：管好多台机器，也让 Codex 别跑错片场

我本机 SSH 配置里的 homelab、debian-dell、pvenode 都是真名；地址、端口、用户和密钥当然不是。

2026-08-09Shubo6 min

机器少的时候，我靠记忆连 SSH。机器多了以后，办法升级成 history | grep ssh。它有时能找到昨天的命令，有时能挖出一段自己都不敢运行的历史文物。

等我开始让 Codex 上服务器查问题，事情更刺激了。“去服务器看看”这句话对人已经够含糊，对 AI 基本等于把车钥匙递过去，然后不说目的地。

先把 IP 从脑子里删掉

我的 ~/.ssh/config 里有 homelab、debian-dell、debian-dell-lan、pvenode 和 pvenode-ssh。下面保留真实 alias，其余全部脱敏：

Host homelab
    HostName <REDACTED_HOST>
    User <REDACTED_USER>
    Port <REDACTED_PORT>
    IdentityFile ~/.ssh/<REDACTED_KEY>
    ServerAliveInterval 30
    ServerAliveCountMax 3

以后只需要：

ssh homelab

地址和端口改了，只动配置。日常命令、脚本和给 Codex 的任务都不用跟着搬家。别名最好按角色起；homelab 一眼能认，server-110 只说明起名的人当时想下班。

同一台机器有两条路，就写两个入口

debian-dell 是日常远程入口，debian-dell-lan 是同一台机器的局域网直连。外面的链路坏了，在家还能走 LAN。修远程通道之前，至少先保证自己没被关在门外。

Host debian-dell
    HostName <REDACTED_EXTERNAL_HOST>
    User <REDACTED_USER>
    IdentityFile ~/.ssh/<REDACTED_KEY>
    ProxyCommand <REDACTED_PROXY_COMMAND>

Host debian-dell-lan
    HostName <REDACTED_LAN_IP>
    User <REDACTED_USER>
    IdentityFile ~/.ssh/<REDACTED_KEY>

PVE 那边也一样：pve-debian13、pve-debian13-cf、pve-debian13-frp。机器名不变，后缀说明走哪条路。出故障时少猜一次，就少开一个无用终端。

共享 alias，别顺手共享私钥

我不会把整个 ~/.ssh 扔进 Git。哪怕仓库是 private，Git 历史也很擅长记住那句“我等会儿删”。更稳妥的拆法是：

~/.ssh/config
~/.ssh/config.d/
├── 00-shared.conf       # 通用选项和 Host 命名
└── 90-local.conf        # 地址、用户、密钥和代理

~/dotfiles/shell/
├── aliases.shared.zsh
├── aliases.macos.zsh
└── aliases.linux.zsh

主配置只负责加载：

Include ~/.ssh/config.d/*.conf

共享的 shell alias 保持简单：

alias h='ssh homelab'
alias dell='ssh debian-dell'
alias dell-lan='ssh debian-dell-lan'
alias pve='ssh pvenode'

alias gs='git status --short --branch'
alias gl='git log --oneline --decorate -12'

需要参数或条件判断就写 function。八十个字符的管道塞进 alias，不叫效率，叫给半年后的自己埋雷。

告诉 Codex 门牌号，也告诉它房间号

让我去 homelab 检查项目时，我会把机器、目录和第一组只读命令一起写出来：

目标机器：homelab
远端目录：<REMOTE_PROJECT_DIR>

先执行并报告：
1. hostname
2. pwd
3. git status --short --branch
4. git rev-parse HEAD

只操作 homelab，不要连接其他机器。
先只读检查；修改和重启按任务范围进行。

对应的第一条命令通常就是：

ssh homelab '
  cd <REMOTE_PROJECT_DIR> &&
  hostname && pwd &&
  git status --short --branch &&
  git rev-parse HEAD
'

这样能先确认机器、目录、分支和 SHA。服务返回 200 只能证明“某处有东西活着”，不能证明你刚改的版本在那里。

经常跨机器的仓库，我还会在 AGENTS.md 放一份短路由表：

## Machine routing

- homelab: personal services; read-only checks by default.
- debian-dell: default remote workstation route.
- debian-dell-lan: LAN rescue route for the same workstation.
- pvenode: virtualization host; explicit scope required.

改完 alias，先问 OpenSSH 自己

ssh -G 会打印最终解析结果，但不发起连接。用它检查旧配置有没有抢先匹配、密钥和 ProxyCommand 是否生效：

ssh -G debian-dell
ssh -G debian-dell-lan
输出里可能有真实主机名、用户名、密钥路径和代理配置。自己看可以，截图发帖前记得脱敏。本文只公开 Host alias。

我的最小规则就五条：机器按角色命名；同机不同路径加后缀；共享 alias，不共享私钥；远程操作先报 hostname、cwd、branch 和 SHA；给 Codex 的任务必须写 alias 和目录。

机器不会因此变少，但至少下一次凌晨排障时，不用先猜自己在哪。
